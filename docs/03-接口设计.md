# 03 接口设计

## 1. 约定

| 项 | 约定 |
| --- | --- |
| 协议 | HTTP/1.1，REST 风格，JSON（`application/json;charset=UTF-8`） |
| 前缀 | 无统一前缀，路径按资源命名（`/home`、`/categories`、`/novels`、`/rank`、`/search`、`/cache`），由各 Controller 自己声明 |
| 方法 | 当前全部为查询接口（`GET`）与缓存清理（`DELETE`），无业务写接口 |
| 分页参数 | `page`（从 0 开始，默认 0）、`size`（默认见各接口） |
| 时间格式 | ISO-8601 字符串（如 `2026-06-12T23:35:25.389797`） |
| 空字段 | `spring.jackson.default-property-inclusion=non_null`，null 字段不输出 |
| 跨域 | `/**` 支持 CORS，来源由 `app.cors.allowed-origins` 控制 |
| 签名 | 可开关的 HMAC-SHA256 签名（`app.signature.*`），密钥为空时不校验 |

### 接口签名

`app.signature.secret` 配置后所有接口要求签名（密钥为空或 `enabled=false` 时完全放行，本地与前端无感知）。

待签名串（换行拼接，无尾换行）：

```text
METHOD \n requestURI \n timestamp \n nonce \n bodySha256Hex
```

`signature = 小写十六进制 HMAC-SHA256(secret, 待签名串)`，随请求发送 4 个头：

| 头 | 说明 |
| --- | --- |
| `X-App-Key` | 应用标识，服务端配置了 `app.signature.app-key` 时须一致 |
| `X-Timestamp` | 秒级时间戳（毫秒也可），与服务端偏差超过 `time-window-seconds`（默认 300）即拒绝 |
| `X-Nonce` | 随机串，同一 nonce 只能使用一次（存于 `signature-nonce` 缓存，防重放） |
| `X-Signature` | 签名值 |

校验不通过返回 `401`，`message` 说明原因（缺少头 / `Invalid signature` / 时间窗外 / nonce 重放）。

- multipart 上传（EPUB 文件）的 body 由 Controller 流式读取，签名时 **body 哈希按空串计算**
- `OPTIONS` 预检不校验；`app.signature.exclude-paths` 中的路径免签（Ant 模式）
- 部署脚本的健康检查在配置了 `APP_SIGNATURE_KEY` / `APP_SIGNATURE_SECRET` 时会自动带签名头

### MCP（Model Context Protocol）

端点：`POST /mcp`（JSON-RPC 2.0，Streamable HTTP，单条 JSON 响应）；`GET /mcp` 返回 SSE 心跳流，`DELETE /mcp` 结束会话（服务端无状态，仅回 204）。

支持的方法：

| 方法 | 说明 |
| --- | --- |
| `initialize` | 返回 `protocolVersion`（默认 `2025-06-18`，客户端版本已支持时原样回显）、`capabilities.tools`、`serverInfo`、`instructions` |
| `notifications/initialized` | 通知，返回 `202` 无响应体 |
| `tools/list` | 工具清单（含 `inputSchema`） |
| `tools/call` | 调用工具，返回 `content[].text` 与 `structuredContent`；业务错误以 `isError=true` 的 **result** 返回（不是 JSON-RPC error） |
| `ping` / `resources/list` / `prompts/list` | 心跳 / 空资源 / 空提示词 |

工具：

| 工具 | 必填 | 可选参数 | 说明 |
| --- | --- | --- | --- |
| `upload_epub` | `fileName`、`contentBase64` | `categoryId`、`categoryName`、`status`、`tags` | 导入 EPUB：解析章节、提取封面、落盘并去重（内容哈希重复即拒绝）。`categoryId` 省略时按 `categoryName`（**不存在即自动创建**），再省则取 `app.upload.default-category-name` |
| `update_novel` | `id` | `title`、`author`、`description`、`status`、`tags`、`categoryId` | 更新书目元数据，只改传入字段；刷新首页/详情/章节缓存（`categoryId` 必须是已存在的分类） |
| `list_categories` | — | — | 分类 id 与名称，上传前查 `categoryId` |
| `list_novels` | — | `limit`（1-100，默认 20） | 书目 id 列表（按更新时间倒序），更新前查 `id` |

鉴权：`app.mcp.token`（留空回退 `app.admin.token`），请求头 `Authorization: Bearer <token>` 或 `X-Mcp-Token`；未通过返回 `401`。`/mcp` 默认在 `app.signature.exclude-paths` 中（MCP 客户端无法签名）。

```bash
curl -X POST http://localhost:8080/mcp -H 'Content-Type: application/json' \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

客户端配置示例（`streamable-http`）：

```json
{
  "mcpServers": {
    "novel-browse": {
      "type": "streamable-http",
      "url": "http://<host>/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### 统一错误结构 `ApiError`

```json
{
  "timestamp": "2026-10-10T15:36:06.481828Z",
  "status": 404,
  "error": "Not Found",
  "message": "小说不存在：id=9999",
  "path": "/novels/9999"
}
```

| HTTP 状态 | 触发条件 |
| --- | --- |
| 404 | 业务对象不存在（`NotFoundException`）；请求路径无对应处理器或静态资源 |
| 400 | 参数缺失 / 类型不匹配 / 参数校验失败 / `IllegalArgumentException` |
| 500 | 其他未捕获异常（服务端已记录堆栈日志） |

### POST /admin/novels

后台上传 EPUB，`Content-Type: multipart/form-data`。

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | EPUB 文件（`.epub`），大小受 `spring.servlet.multipart.max-file-size` 限制 |
| `categoryId` | 否 | 分类 id，不存在时返回 404；优先于 `categoryName` |
| `categoryName` | 否 | 分类名，不存在时自动创建（初始库为空，可不建分类直接上传） |
| `status` | 否 | `ONGOING`（默认）/ `FINISHED` |
| `tags` | 否 | 逗号分隔；留空取 EPUB 的 `dc:subject` |

两者都不传时归入 `app.upload.default-category-name`（默认 `Imported`，不存在则创建）。

解析规则：zip → `META-INF/container.xml` → OPF；按 `spine` 顺序抽取正文，一个文档一章，单文档含多个 `h1/h2` 且正文超过 3000 字时按标题切分；元数据取 `dc:title`、`dc:creator`、`dc:description`；正文为空的资源（图片、样式、导航）跳过。入库时在同一事务写入 `chapter_count` / `word_count` / `updated_at`，并让首页相关缓存整体失效。

封面：EPUB 内嵌封面会在导入时提取并写入 `app.cover.dir`（文件名 `<内容哈希前8位>-cover.jpg`），接口以 `coverUrl`（`/covers/<file>`）返回；EPUB 没有封面时 `coverUrl` 不输出，前端回落 `coverColor` + `coverMark`。删除书目会同时删除其封面文件。

落盘与去重：原文件先保存到 `app.upload.dir/<分类名>/`（文件名 `内容哈希前8位-原名.epub`，分类目录不存在则创建），再解析入库；`novel.source_file` 保存相对路径 `分类名/文件名`。

判重分两层：

| 命中 | 行为 |
| --- | --- |
| 内容 SHA-256 相同（同一个文件重复上传） | 400，不落盘 |
| 书名 + 作者相同（同一本书换了字节，例如重新生成的 EPUB） | **覆盖**：沿用原 id，替换简介/标签/状态/封面/章节（先删旧章节再写新的），保留 `view_count`、`rating`、`created_at`；删除上一版的源 EPUB 与旧封面文件 |

覆盖对管理端上传、MCP `upload_epub`、启动目录扫描三条入口一致，因此磁盘上残留的重复副本会在下次启动时被吸收而不是变成新书。解析失败会删除刚落盘的文件，避免启动时被当成新书。

启动时（`EpubAutoLoader`）按目录双向同步：

| 方向 | 行为 |
| --- | --- |
| 子目录 → 分类 | 目录名即分类名，不存在则创建（sortNo=999 排最后），目录内 EPUB 导入该分类 |
| 分类 → 子目录 | 为已有分类补齐缺失目录（`app.upload.ensure-category-dirs`，默认 true） |
| 根目录文件 | 归入 `app.upload.default-category-name`（默认 `Imported`），不建子目录 |

已导入的文件按哈希跳过，单个文件解析失败只记 ERROR 并继续。

删除：会连同磁盘上的 EPUB 原文件一起删除，否则下次启动会被重新导入。

成功返回 `201` + `NovelSummary`：

```json
{ "id": 9, "title": "测试之书", "author": "测试作者", "categoryId": 1, "categoryName": "玄幻奇幻",
  "status": "FINISHED", "statusText": "完结", "tags": ["玄幻", "测试"],
  "wordCount": 248, "chapterCount": 3, "viewCount": 0 }
```

错误响应：

| 场景 | 状态码 | message |
| --- | --- | --- |
| 非 `.epub` 后缀 | 400 | `Only EPUB files (.epub) are supported: bad.txt` |
| 不是合法 zip / 缺少 container.xml 与 opf | 400 | `Not a valid EPUB (missing META-INF/container.xml and .opf): ...` |
| 解析不出任何章节 | 400 | `No chapter content could be parsed from the EPUB: ...` |
| 缺少 `file` 字段 | 400 | `Required part 'file' is not present.` |
| 文件超出大小限制 | 413 | `Uploaded file is too large: ...` |
| 内容重复（同一 EPUB 已导入） | 400 | `This EPUB was already imported (content hash 6e6e83a8)`（书名 + 作者相同但字节不同时不报错，走覆盖） |
| 分类不存在 | 404 | `Category not found: id=9999` |
| `app.admin.token` 已配置且令牌缺失/错误 | 401 | `Missing or invalid X-Admin-Token` |
| 签名校验失败 | 401 | `Invalid signature` / `Missing signature header: X-Timestamp` / `Request timestamp out of the allowed window (300s)` / `Replayed request (nonce already used)` |

### GET /admin/novels

返回 `NovelSummary[]`，按 `updatedAt` 倒序。

### DELETE /admin/novels/{id}

删除书目及其全部章节，返回 `204`；书目不存在返回 `404`。

清空指定缓存，返回 `{ "name": "novel-detail", "cleared": true }`；缓存名不存在返回 404。

### 读者账户：注册 / 登录 / 登出

登录态靠 cookie：注册或登录成功后响应头带上

```
Set-Cookie: nb_session=<token>; Path=/; Max-Age=2592000; Expires=...; HttpOnly; SameSite=Lax
```

默认 30 天（`app.auth.session-days`）。cookie 里只有随机 token，服务端 `nb_user_session`
记录归属与过期时间，登出即删除该行，因此可以在服务端强制失效；会话过期后请求返回 401。

- 前端跨域必须带凭证：`fetch(url, { credentials: 'include' })` 或 axios `withCredentials: true`，服务端已开
  `Access-Control-Allow-Credentials`
- 密码用 BCrypt 存储，接口永不返回密码或哈希
- 未登录 / token 无效 / 会话过期 → 401 `{"message":"Login required"}`

注册 `POST /auth/register`，body `{"username":"reader","email":"reader@example.com","password":"secret123"}` → 200
`UserView` + cookie：

| 情况                         | 状态 | message                                                              |
|------------------------------|------|----------------------------------------------------------------------|
| 用户名已被占用（忽略大小写） | 400  | `Username is already taken: reader`                                  |
| 邮箱已注册（忽略大小写）     | 400  | `Email is already registered: reader@example.com`                    |
| 邮箱格式不合法               | 400  | `Email is not valid: xxx`                                            |
| 密码不在 8-64 位             | 400  | `Password must be 8-64 characters`                                   |
| 用户名含非法字符或长度不符   | 400  | `Username must be 2-32 characters` / `Username may only contain ...` |

登录 `POST /auth/login`，body `{"email":"reader@example.com","password":"secret123"}`，`email` 也可填用户名。密码错误与账号不存在统一返回
401 `Email or password is incorrect`（不区分，避免账号枚举）。

登出 `POST /auth/logout` → 204，cookie 置 `Max-Age=0`。

### 权限边界

| 类别   | 接口                                                                                                                                                                                                                                         | 是否需要登录                                        |
|--------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------|
| 浏览   | `GET /home`、`/categories`、`/categories/{id}`、`/categories/{id}/novels`、`/novels`、`/novels/{id}`、`/novels/{id}/chapters`、`/novels/{id}/chapters/{no}`、`/novels/{id}/chapter-page`、`/novels/chapters/{chapterId}`、`/rank`、`/search` | **不需要**，匿名可看                                |
| 互动   | `GET/POST/DELETE /me/likes...`、`/me/favorites...`、`/me/progress...`、`/me/reviews...`、`GET /auth/me`                                                                                                                                      | **必须**，未登录 401 `{"message":"Login required"}` |
| 公开读 | `GET /novels/{id}/reviews`                                                                                                                                                                                                                   | 不需要                                              |

未登录访问互动接口一律 401，前端应据此弹登录；浏览接口不会因为没登录而被拦。

### 书架与阅读进度

- `POST /me/favorites/{novelId}` 幂等，重复加入不会产生第二条；`GET /me/favorites?page=0&size=20` 返回
  `PageResult<NovelSummary>`
- `PUT /me/progress/{novelId}` 提交 `{"chapterNo":2}`；`chapterNo` 从 1 起，超过该书总章节数返回 400
  `chapterNo must not exceed the chapter count: n`，书目不存在返回 404
- 需要登录的接口在未登录时统一 401

### 评论与评分

- 一个读者对一本书只保留一条记录：`PUT /me/reviews/{novelId}` 是「发表或更新」
- `rating` 必须 1-5，越界返回 400 `rating must be between 1 and 5`；评论正文最多 1000 字
- 保存或删除后回写 `nb_novel.rating`（星均分 ×2，落到 0-10 一位小数）与 `nb_novel.rating_count`，并清首页与详情缓存
- `GET /novels/{id}/reviews` 公开，按发表时间倒序

## 5. 前端对接建议

1. 首屏：`GET /home` 一次拿到分类与各类书单；
2. 列表页：优先 `/categories/{id}/novels` 与 `/rank`，统一消费 `PageResult`；
3. 详情页：`/novels/{id}` + `/novels/{id}/chapter-page`；
4. 阅读页：`/novels/{id}/chapters/{no}`，按 `prevNo / nextNo` 翻章；
5. 错误统一依据 `status` 与 `error` 字段处理，避免依赖 `message` 文案。
