## 设计总览

| 维度 | 结论 |
| --- | --- |
| 形态 | 单体 Spring Boot 服务，对外暴露 JSON REST 接口（`GET` 只读场景），无页面渲染层 |
| 数据 | H2 内存库 + JPA（Hibernate）；进程启动时建表，不含种子数据（书目全部来自 EPUB 导入），退出即释放 |
| 缓存 | 进程内嵌 RocksDB 作为缓存实现（自实现 `CacheManager`，非 Redis），降低热门书目与章节正文的数据库压力 |
| 读多写少 | 当前仅“详情页点击数自增”一个写操作，其余全为查询，因此采用本地读缓存即可获得高收益 |
| 一致性 | 采用容错优先策略：缓存不可用时按未命中处理，不影响业务正确性 |
| 演进 | 数据量增长后可平滑替换为外部关系库 + Redis，接口层保持不变（见 05 文档） |

## 关键约束

1. 工程不含任何书目种子数据：分类与书目均在 EPUB 导入时创建，不涉及第三方版权内容。
2. 内存库每次重启会重新生成主键，因此 RocksDB 本地缓存默认启动时清空（`rocksdb.cache.clean-on-start=true`）。
3. 所有接口为幂等查询；写操作（点击数）不返回业务结果，仅自增并失效对应缓存。
