# 05 构建部署与配置

## 1. 构建体系

| 项 | 值 |
| --- | --- |
| 构建工具 | Gradle 9.6.0（含 Wrapper，`gradlew` / `gradlew.bat`） |
| Wrapper 发行包地址 | `https://mirrors.cloud.tencent.com/gradle/gradle-9.6.0-bin.zip` |
| 插件 | `org.springframework.boot` 4.1.1、`io.spring.dependency-management` 1.1.7 |
| Java 工具链 | `JavaLanguageVersion.of(21)` |
| 编码 | 编译与测试均显式 UTF-8 |
| 产物 | `build/libs/novel-browse.jar`（可执行 fat jar） |

常用命令：

```bash
./gradlew clean build      # 编译 + 打包 + 静态检查（跳过测试可用 -x test）
./gradlew bootRun          # 直接运行
java -jar build/libs/novel-browse.jar
```

## 2. 仓库镜像配置

`settings.gradle` 中集中配置，避免每个构建脚本重复声明：

| 用途 | 仓库 |
| --- | --- |
| 插件解析 `pluginManagement` | 腾讯云 `maven-public` → `gradlePluginPortal()` 兜底 |
| 依赖解析 `dependencyResolutionManagement` | 腾讯云 `maven-public` → `mavenCentral()` 兜底 |

说明：

- Spring Boot Gradle 插件标记在腾讯云镜像即可拉取；`io.spring.dependency-management` 的插件标记只在插件门户发布，因此必须保留 `gradlePluginPortal()` 兜底。
- 腾讯云镜像同步存在延迟时（如新版本 rocksdbjni 尚未同步），依赖会自动回落到中央仓库。

## 3. 运行依赖与端口

| 项 | 说明 |
| --- | --- |
| 端口 | `server.port=8080` |

| H2 控制台 | `/h2-console`，账号 `sa`，密码为空；仅限开发使用 |

## 6. 部署建议

| 环境 | 建议 |
| --- | --- |
| 本地开发 | `./gradlew bootRun`，前端 dev server 通过 `app.cors.allowed-origins` 放开；可用 `/h2-console` 查库 |
| 测试 / CI | `./gradlew clean build`，产物以 `java -jar` 启动；无需外部中间件 |
| 生产（单实例） | 关闭 H2 控制台；`allowed-origins` 改为具体域名；`rocksdb.cache.path` 指向独立数据盘；建议外接 MySQL/PostgreSQL |
| 生产（多实例） | 嵌入式 RocksDB 无法跨实例共享，需切换 Redis 作为缓存（替换 `CacheManager` Bean 即可，业务注解不变） |

容器化示例（可选）：

```dockerfile
FROM eclipse-temurin:21-jre
WORKDIR /app
COPY build/libs/novel-browse.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java","-jar","/app/app.jar"]
```

### 6.1 服务器部署（scripts/）

Ubuntu 服务器采用「版本目录 + current 软链接」的发布方式，脚本见 [`scripts/`](../scripts/README.md)。

| 脚本 | 用途 |
| --- | --- |
| `deploy.sh` | 一键部署：拉码 → 构建 → 发布新版本 → 切换 → 重启 → 健康检查（失败自动回滚）→ 清理旧版本 |
| `app.sh` | 日常运维：`start` / `stop` / `restart` / `status` / `health` / `log` / `releases` |
| `install-service.sh` | 安装 systemd 单元与 logrotate 配置（需 sudo） |
| `deploy.conf.example` | 部署配置样例（端口、JVM 参数、分支、保留版本数等） |

服务器上的目录结构（脚本与源码平级；脚本放在仓库内也能自动识别）：

```text
~/source/
├── novel-browse/                源码仓库（git clone 位置）
└── scripts/                     部署脚本

~/apps/novel-browse/             部署根目录（APP_ROOT）
├── releases/<commit>-<时间>/    历次发布（app.jar + release.env）
├── current -> releases/xxx      当前生效版本（软链接）
├── logs/novel-browse.log        运行日志
├── run/novel-browse.pid         pid 文件（nohup 模式）
└── data/rocksdb-cache/          RocksDB 缓存目录
```

```bash
cd ~/source/scripts
./deploy.sh                 # 部署最新代码
./deploy.sh --skip-pull     # 用当前工作区代码部署
./deploy.sh --rollback      # 回滚到上一个版本
./app.sh status             # 查看版本、进程与健康检查
```

设计要点：源码目录 `SOURCE_DIR` 自动探测（`../novel-browse` 优先，其次 `..`），也可在 `deploy.conf` 中显式指定；健康检查失败自动回滚；`KEEP_RELEASES` 控制历史版本保留数（当前版本始终保留）；`MANAGER=auto` 时存在 systemd 单元则用 systemctl，否则用 nohup（无需 root）。

## 7. 监控与运维

| 能力 | 当前状态 |
| --- | --- |
| 缓存观测 | `GET /cache`（命中率、写入数、条目数）、`DELETE /cache/{name}` |
| 日志 | `logback-spring.xml`：控制台输出（部署脚本重定向到 `logs/novel-browse.log` + logrotate）；级别用 `LOG_LEVEL_APP` 或 `--logging.level.com.novel.browse=DEBUG` 切换；`SPRING_PROFILES_ACTIVE=file` 时由日志框架自写滚动文件 |
| 健康检查 | 未接入 Actuator，可按需引入 `spring-boot-starter-actuator` |
| 指标导出 | 未接入 Micrometer，可将 `CacheStats` 注册为 Gauge 暴露 |

## 8. 演进规划

| 阶段 | 目标 | 关键动作 |
| --- | --- | --- |
| 一 | 数据持久化 | 替换为 MySQL / PostgreSQL，引入 Flyway 管理 DDL，移除 `ddl-auto=update` |
| 二 | 后台与写入 | 增加书籍 / 章节的增删改接口，统一在同一事务内维护 `chapter_count`、`word_count`、`updated_at`，并配套 `@CacheEvict` |
| 三 | 缓存升级 | 多实例场景切换 Redis；或引入二级缓存（本地 RocksDB + Redis） |
| 四 | 安全与租户 | 引入认证鉴权（Spring Security / OAuth2），收敛 CORS，增加限流 |
| 五 | 检索能力 | 书名全文检索可引入 Elasticsearch / MySQL 全文索引，替代当前的 `LIKE` 查询 |
| 六 | 可观测 | 接入 Actuator + Micrometer + 链路追踪，将缓存指标纳入监控 |
